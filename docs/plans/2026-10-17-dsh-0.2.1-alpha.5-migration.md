## 改动

- `package.json`：version `0.7.1` → `0.7.2`；devDependencies `@deepseek-ai/cordis` `^4.0.1` → `~4.0.5-alpha.2`、`@deepseek-ai/schemastery` `^3.18.4` → `~3.18.5-alpha.2`（J1-18 注12：提高 range 让重链落到正确版本是持久修复；本仓库 lockfile 在 .gitignore，无 lockfile diff 顾虑）；新增 `@types/react-dom` `~18.3.7`；`typecheck` script 增 tests 通道。
- `tsconfig.tests.json`（新增）：extends 主 tsconfig，`rootDir: "."`（避 TS6059）、`noEmit`，include `src`+`tests` —— 固化「tests 进 typecheck」，堵 J1-19 静默 fixture 负债通道。
- `tests/brand-text.client.spec.tsx`：补 `usePanelInfo` stand-in（`GlobalStandardProps` 自 **0.2.0-rc.2** 由 ui-layout 合入 `usePanelInfo: UsePanelInfo`；本插件 tests 从未进 tsc 故从未暴露——归因：存量负债，非本次跳变新增）；render props 传入。
- `tests/stubs/store.ts`：删未用 `vi` import（TS6133）。
- `tests/controller.spec.ts`：`init` → `_init`（TS6133）。
- `tests/registration.client.spec.ts`：stub 接口 `locale.register` 的 `dict: unknown` → `Record<string, string>` 对齐实现（TS2322，文件内自负债）。
- `README.md`：开发前置段更新到 alpha.5 基线（peers/vendored pin/junction 绝对路径/typecheck 双通道）。
- 重建 `lib/`（tsdown + tsc；client bundle 仍为 externals-only + `window.__ModuleLoader__.load` 包裹，运行期 require 仅 `@deepseek-ai/dsh-client-store`/`react`/`react/jsx-runtime`，全在模块表基线内）。
- 本机清理（不入库，文件在 .gitignore）：`pnpm-workspace.yaml` 删陈旧 `minimumReleaseAgeExclude: '@deepseek-ai/schemastery@3.18.4'`（J1-18 注5 点名的回归通道）；`node_modules/@deepseek-ai/{cordis,schemastery}` 由陈旧 store symlink（4.0.1/3.18.4）换为指向 `dsh/vendor/` 的绝对路径 junction，随后 devDep bump 触发 pnpm ≥12 `verify-deps-before-run` 从 store 重链到 4.0.5-alpha.2 / 3.18.5-alpha.2。

## 验证

- junction 探测（分层归因）：typecheck 走 tsconfig paths 直连 dsh 树（不受 node_modules 影响）；vitest 唯一值导入 `dsh-client-store` 经 stub 别名；build externals-only——三通道本就不经过 node_modules 的 `@deepseek-ai`，陈旧链接是潜在（非现实）假绿源，已消除。
- `pnpm typecheck`（src + tests 双 tsconfig）：0。
- `pnpm test`：36 passed / 5 files（迁移前基线同为 36 passed，无回归、无存量失败）。
- `pnpm run build`：0；build 后 `lib/` 复扫已移除符号：零命中。
- `pnpm peers check`：仅 `@napi-rs/wasm-runtime@1.2.3` 的 `@emnapi/*` 可选 peer 噪音（jsdom/tsdown 工具链传递引入），与 `@deepseek-ai` 无关，存量。
